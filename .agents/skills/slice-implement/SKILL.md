# slice-implement

## 시작 전
- 이번에 할 단계 번호와 산출물을 PLAN에서 찾아 한 줄로 말한다. 단계가 지정되지 않았으면 묻는다.
- 바꿀 파일 목록을 먼저 말한다. `src/` 밖(검증 세션 소유 파일)은 건드리지 않는다.

## 구현
- 그 단계에 필요한 최소한만 만든다. 다음 단계 코드를 미리 쓰지 않는다.
- 업무 기준은 이름 있는 상수·함수로 둔다 (예: `MIN_STOCK = 10`, `classify_order()`).
- 데이터를 거르거나 분류하면 개수 대사를 출력하거나 테스트로 확인한다.
- 서버는 `0.0.0.0` 바인딩.

## 확인
- 실제로 실행한다: 테스트, 스크립트, 서버라면 `curl` 응답. 가능하면 `bash scripts/smoke.sh`.
- 실행하지 못했으면 "미확인"이라고 쓴다. 확인한 척하지 않는다.

## 실패했을 때
1. 고치기 전에 원인 가설과 근거(에러 메시지 핵심 줄)를 말한다.
2. 한 번에 한 가지만 바꾼다.
3. 같은 문제로 3번 실패하면 멈추고 선택지(범위 축소, 다른 방식, 담당자 확인)를 보고한다.

## 끝
```
변경: <파일>

위험: <남은 문제>
```
그리고 `feat: <단계 이름>` 형식으로 커밋하고 멈춘다. 다음 단계는 사람이 지시한다.
