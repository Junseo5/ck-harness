# AGENTS.md — 공통 규칙 (모든 세션)

사람(리드)이 판단하고, AI 세션은 역할별로 위임받은 작은 단위를 수행한다.
각 세션의 역할(dev · analyst · reviewer)은 실행 시 따로 주어진다.
역할 지시가 없으면 세션 하나로 진행하는 것이다: 세 역할을 모두 맡아 아래 표의 모든 곳에 쓸 수 있고,
스킬마다 그 스킬의 주 사용 역할 관점으로 일한다. 검증할 때는 `.harness/roles/reviewer.md`를 읽고 src 로직을 따라 하지 않는다.
대회·과제별 맥락과 추가 규칙은 이 파일 끝의 "이벤트" 섹션에 있고, 공통 규칙보다 우선한다.

## 1. 세션과 파일 소유권
| 역할 | 실행 | 쓸 수 있는 곳 |
|---|---|---|
| dev | `bin/dev` | `src/`, 테스트, 실행 설정, README |
| analyst | `bin/analyst` | `docs/COLLAB.md`, `docs/PLAN.md`, `docs/DECISIONS.md` |
| reviewer | `bin/reviewer` | `verify/`, `docs/VERIFY.md` |
- 역할이 주어진 세션은 자기 소유가 아닌 파일을 수정하지 않는다. 필요하면 해당 역할에 넘길 요청 문장을 만든다.
- 서브에이전트는 사람이 명시적으로 요청할 때만 띄운다. `explorer`는 읽기 전용(데이터 점검, 로그 분석, 결과 요약)이다.
- 추가 세션은 `docs/PLAN.md`에 파일 소유권이 적힌 경우에만 쓴다.

## 2. 공통 원칙
- 불명확하면 추측하지 않는다. 요구를 준 사람에게 물을 질문으로 정리해 돌려준다.
- 요청받은 범위만 한다. 끝나면 멈추고 보고한다.
- 요구를 충족하는 가장 단순한 구현을 고른다. 요구에 없는 계층·설정·옵션·방어 코드는 결함으로 본다.
- 실패를 성공처럼 보이게 하지 않는다. 예외를 삼키거나, 빈 결과를 정상으로 내거나, 테스트를 약화하지 않는다.
- 완료·통과를 말하기 전에 확인 명령을 지금 다시 실행하고 출력을 근거로 든다. 못 했으면 "미확인".
- 데이터를 거르거나 분류하면 개수를 대사한다: `입력 = 포함 + 제외 + 확인필요`. 안 맞으면 멈춘다.
- 대량 데이터·로그를 통째로 출력하지 않는다. 개수·요약·샘플로 보여준다.

## 3. 보고 형식
```
변경: <파일 목록>
확인: <실행 명령> → <결과 요약>
위험: <남은 문제·가정, 없으면 "없음">
```

## 4. 문서 (docs/)
PLAN(계획·소유권) · COLLAB(요구 문답) · DECISIONS(결정·버린 대안·AI 제안을 바꾼 지점) · VERIFY(검증).
인수인계(실행·결과·한계·다음 할 일)는 프로젝트 README에 쓴다. 결정과 문답은 생긴 즉시 짧게 기록한다.
`.harness/`는 작업 도구(역할·스크립트·템플릿)이며 결과물이 아니다. 수정하지 않는다.

## 5. 환경
- 원격·컨테이너 환경에서 서버를 띄우면 `0.0.0.0`에 바인딩한다. 포트는 PLAN에 적는다.
- API 키·토큰·비밀값을 만들거나 요구하거나 코드에 넣지 않는다.
- 커밋은 단계마다, 메시지는 한국어: `feat:` `fix:` `docs:` `test:` `chore:`.
- 무거운 프로세스(빌드·서버)는 동시에 여러 개 띄우지 않는다. 끝난 서버는 종료한다.

## 6. 스킬 (진행 순서)
| 스킬 | 시점 | 주 사용 역할 |
|---|---|---|
| `$intake-interview` | 시작 직후: 과제·데이터 파악, 질문 사다리 | analyst |
| `$plan-gate` | 범위 합의 후: PLAN 작성·점검·승인 | analyst → 사람 |
| `$slice-implement` | 구현 단계마다 | dev |
| `$verify-loop` | 기본판 동작 후: 독립 검증·두 단계 리뷰 | reviewer |
| `$risk-audit` | 기능 동결 후: 약점 정리·설명 예행연습 | reviewer 또는 dev |
| `$handoff` | 마감 전: README 인수인계 | dev |
| `$submit-check` | 제출 직전 점검 | dev |
시간 기준점과 제출 절차는 이벤트 섹션을 따른다.
