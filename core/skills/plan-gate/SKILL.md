# plan-gate

## 입력
`docs/COLLAB.md`의 합의 내용, 데이터 요약, 과제 문서.

## 작성 (docs/PLAN.md, 30줄 이내)
1. 목표 한 문장: 누가, 무엇을 할 수 있게 되는가
2. 범위 안 / 범위 밖 (범위 밖을 반드시 적는다)
3. 성공 기준: 확인 가능한 형태(예: "입력 120건이 포함/제외/확인필요로 빠짐없이 나뉜다")
4. 기술 선택: 언어·프레임워크·실행 명령·포트. 이유 한 줄. 가장 단순한 것을 고른다.
5. 단계 표: 단계마다 산출물과 확인 방법. 각 단계는 15~25분 분량.
   1단계는 "처음부터 끝까지 가장 얇게 동작하는 기본판"이다.
6. 파일 소유권: 메인 세션 = `src/`, 검증 세션 = `verify/`. 추가 세션을 쓸 경우 파일을 명시.
7. 위험과 가정: 담당자 답이 없어서 가정한 것

## 비판 점검 (PLAN 맨 아래 3줄)
작성한 PLAN을 반대 입장에서 한 번 본다.
- 가장 약한 가정: 틀리면 무엇이 무너지는가
- 가장 먼저 깨질 곳: 데이터·요구 중 어디서 문제가 날 가능성이 큰가
- 더 단순한 대안: 같은 성공 기준을 더 적은 코드로 맞출 방법이 있는가
점검 결과 바꿀 것이 있으면 PLAN을 고친 뒤 게이트로 간다.

## 게이트
- 작성 후 PLAN 요약을 보여주고 **"승인하면 1단계부터 `$slice-implement`로 진행"** 이라고 묻고 멈춘다.
- 사람이 고치라고 하면 PLAN만 고친다. 승인 전에는 `src/`에 아무것도 만들지 않는다.
- 승인되면 `docs/DECISIONS.md`에 기술 선택과 버린 대안을 적고 `docs: 계획 확정` 으로 커밋한다.
