## 세션 구성
- 터미널 1: `bin/dev` (구현, `src/`)
- 터미널 2: `bin/analyst` (0:00~, `docs/`) → `bin/reviewer` (1:30~, `verify/`)
- 세션 수 제한은 없지만 오른쪽 위 RAM을 본다. 읽기 작업은 dev 안에서 "explorer 서브에이전트로 ○○ 요약해줘"
- reviewer 지적은 dev에 붙여 넣는다 (dev는 검토 후 반영·반박)
- 나: Codex가 일하는 동안 담당자 문답, 결정 승인
- AI 제안을 내가 바꾸면 analyst에 "DECISIONS에 기록: <AI 제안> → <바꾼 내용>, 이유 <한 줄>"
- 역할 확인: 세션 첫 질문 "너의 역할과 쓸 수 있는 폴더를 한 줄로"

## 세션을 하나만 쓸 때
- `codex`를 그냥 켠다(`bin/dev`로 켜지 않는다). 역할 지시가 없으면 한 세션이 세 역할과 모든 문서를 맡는다.
- 순서는 같다: `$intake-interview` → `$plan-gate` → `$slice-implement` → `$verify-loop` → `$risk-audit` → `$handoff` → `$submit-check`
- 대화가 길어지면 `/new`. 합의와 진행은 docs/에 있으니 "docs/PLAN.md 읽고 N단계부터"로 이어 간다.
- 검증은 `/new` 뒤에 `$verify-loop` (구현 대화를 모르는 상태에서 하는 편이 독립적이다)

## 사전 체험 확인 (1분)
- `codex --version`
- `bin/dev` 실행 → 역할 확인 질문에 dev라고 답하는지
- 터미널 2개 동시 실행 시 RAM 표시
- 처음 실행할 때 폴더 신뢰 여부를 물으면 허용 (`.codex/config.toml` 적용 조건)
- Codex가 `git commit` 승인을 요청하면 허용한다. 샌드박스가 `.git` 쓰기를 막으면 커밋이 조용히 실패할 수 있으니 `git log`로 확인

## 프롬프트 카드
1. **데이터 확인**: "데이터 파일마다 행 수, 컬럼, 결측·중복·이상값, 샘플 2개만 요약해줘. 파일 수정 금지."
2. **계획**: "$plan-gate. COLLAB 합의 기준으로 PLAN 30줄 이내. 승인 전 코드 금지."
3. **단계 설계**: "PLAN 2단계를 어떻게 구현할지 바꿀 파일과 접근만 5줄로. 아직 코드는 쓰지 마."
4. **한 단계**: "$slice-implement 2단계만. 끝나면 변경/확인/위험 3줄 보고하고 멈춰."
5. **실패**: "고치기 전에 원인 가설과 근거 에러 줄부터. 한 번에 하나만 바꿔."
6. **독립 검증**: "$verify-loop. src는 읽지 말고 PLAN·COLLAB·원본 데이터로만 기대값을 계산해."
7. **결과 정리**: "$handoff. 숫자는 실제 실행 결과에서만 가져와."
8. **예행연습**: "$risk-audit. 서술형 예상 질문 6개와 4문장 답 뼈대."
9. **이해 점검**: "방금 바꾼 코드에서 입력이 비었을 때 어떤 일이 일어나는지 내가 먼저 말해볼게. 맞는지 확인만 해줘: …"

## 막혔을 때
- 같은 문제 15분 → 범위를 줄이거나 담당자에게 묻는다.
- 숫자가 안 맞으면 멈춘다. 대사부터 맞춘다.
- AI가 "완료"라고 하면: 바뀐 파일 / 개수 대사 / 한 문장으로 설명 가능한지 세 가지를 확인한다.
- 담당자 요구 > 내 아이디어. 요구에 없는 기능은 넣지 않는다.

## 서술형 (문항당 5분, AI·복붙 불가)
4문장, 250~450자:
1. 결론: 파일·함수 이름을 넣어 한 문장
2. 근거: 담당자 답, 데이터, 검증 결과
3. 한계: 내 코드의 약점과 영향
4. 검증: 다음에 무엇을 어떻게 확인할지
