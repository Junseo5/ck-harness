## 이벤트: Cofa-Probe 실무형 AI 협업 과제

### 맥락
- 웹 IDE(E2B 샌드박스)에서 과제 README를 읽고, 오른쪽 메신저의 **업무 담당자(실무자 에이전트)**와 대화하며 최대 180분 안에 동작하는 결과물을 만든다.
  업무 맥락은 담당자에게, 과제 목표·필수 조건·제출물은 과제 README와 안내에서 확인한다. 화면 사용법은 Cofa Helper에게 묻는다.
- 과제 README가 제출 문서의 이름·위치(예: 계획 문서, 협업 기록)를 정하면 그것이 우선이다. `docs/` 양식은 그럴 때 내용 참고용이다.
- 평가는 AI 활용 역량과 문제 해결 과정을 함께 본다. 수집되는 것: Codex·담당자와의 대화, 터미널 세션, git 로그·diff, 테스트 실행 결과, 작업 폴더의 파일. 토큰 사용량도 간접 평가에 쓰일 수 있다.
- 에이전트 응답 시간을 고려한 위임과 시간 배분도 평가 대상이다. 응답을 기다리는 동안 사람이 담당자 문답이나 결과 확인을 하면 시간이 덜 샌다.
- 제출 후 AI 없이 서술형 문항(안내상 6문항, 문항당 5분, 복사·붙여넣기 불가)이 이어지고, 문항은 제출물과 작업 기록에서 만들어진다.
  사람이 설명하지 못하는 코드는 감점 요인이라, 큰 변경을 나눠 이유를 남기며 진행하는 편이 낫다.
- 요구에 없는 기능·과한 설계·쓰지 않는 파일은 완성도가 아니라 감점 요인으로 본다.
  담당자가 실제로 쓰는 장면에 필요한 것을 정확하고 단단하게 만드는 데 시간을 쓴다.

### 시험 규칙 (운영 안내)
- 과제 AI는 제공된 Codex만 쓴다. 권장 모델은 Sol 6.1, Terra 5.6, Luna 6, Sol 6.0이고 Astra는 사용이 제한된다. 개인 API 키·유료 구독·다른 AI 도구는 쓸 수 없다.
- 문제·파일·결과물의 외부 전송은 금지이고 `git push`는 불가하다. 공개 저장소 clone·다운로드는 허용된다. 작업은 로컬 커밋으로 남긴다.
- Computer Use(자동 조작)는 금지다. 화면 확인은 사람이 Browser 미리보기에서 포트·경로를 넣어 한다(서버는 `0.0.0.0` 바인딩).
- 공개 Skill·MCP·GitHub 자료와 외부 코드 참고는 허용되지만, 결과물을 통째로 대체하는 것은 허용되지 않는다.
- 본인 프로세스 때문에 생긴 메모리 초과(OOM)는 구제되지 않는다. 서버·빌드를 겹쳐 띄우지 않고 끝난 프로세스는 종료하는 편이 안전하다.
- Codex와 사람이 같은 파일을 동시에 고치면 에디터에 저장 충돌이 날 수 있다.

### 기준점 (과제 시작 기준 경과 시간)
0:30 범위 합의 · 1:30 기본판 동작 · 2:20 기능 동결 · 2:40 문서 마감 · 2:50 제출 시작(안내 권장: 종료 10분 전)

### 설명 예행연습 형식 (`$risk-audit`)
서술형 6문항, 문항당 5분. 권장 형식은 4문장(250~450자): 결론(파일·함수 이름 포함) → 근거 → 한계 → 다음 검증.
질문의 전제가 실제 구현과 다르면 차이를 밝히고 실제로 한 작업을 설명한다(안내문 권장).

### 제출 절차 (`$submit-check` 마지막 안내)
필수 파일 경로와 저장 상태 확인 → 상단 '제출하고 문제풀기'로 미리보기(숨김 폴더는 생략될 수 있음) → '제출물 확정하고 문제풀기'.
확정 후에는 파일을 고칠 수 없다. 서술형까지 마친 뒤 완료 화면에서 제출 ID·시각·파일 수를 확인한다.
